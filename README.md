# FOUR³

Браузерная 3D-игра «четыре в ряд»: локальная игра вдвоём, три уровня AI, онлайн-лобби по коду и рейтинговая игра со случайным соперником. Собственный дизайн поля, графитовые и светлые фишки. Можно играть гостем или зарегистрировать аккаунт.

## Запуск

Нужен Node.js 24 LTS (используется встроенный SQLite).

```sh
npm install
npm run dev
```

Откройте **http://localhost:5173/**. Команда запускает Vite (5173) и сервер игры (3001). Vite проксирует `/online`, `/auth` и `/health` к Node-серверу. Для второго устройства в той же сети используйте один из адресов Network, который напечатает Vite; оба игрока должны открыть один и тот же сервер. Файрвол должен разрешать подключение к dev-серверу.

```sh
npm run build
npm run preview
```

Preview открывается на **http://localhost:4173/** и поддерживает онлайн. Сборка сайта находится в `dist/`, сервер — в `dist-server/`. Шрифт, геометрия, логика и AI поставляются вместе с приложением. Локальные режимы работают в браузере; онлайн обращается к вашему серверу.

## Сервер

Основной адрес — **https://4inrow.ru/**, `www.4inrow.ru` перенаправляется на него. SSH-алиас на рабочем ПК — `four-game-server`; он подключается к `4inrow.ru`. Публичные запросы, WebSocket и почтовые ссылки используют домен, поэтому смена адреса сервера в DNS не требует правки клиентского кода. Старый сервер недоступен, по решению владельца новый запущен с пустой базой.

Проект и исходники находятся в `/srv/four-game`, данные аккаунтов, статистики и уровней — в `/srv/four-game-data`. Настройки почты и админ-панели лежат отдельно в `/etc/four-game/mail.env` и `/etc/four-game/admin.env` (доступ только root); их нельзя включать в публичный архив исходников. Служба `four-game` запускает Node.js 24 на `127.0.0.1:3001`. Nginx обслуживает HTTPS, HTTP/2 и сжатие файлов. Сертификат для основного домена и www продлевает `certbot.timer`, после продления Nginx перечитывает сертификат.

Шаблоны: `deploy/four-game.service`, `deploy/nginx-domain-http.conf`, `deploy/nginx-domain.conf`. Скрипт `scripts/provision-server.sh` предназначен для первичной установки на Ubuntu с установленными Node.js 24, Nginx и Certbot; ожидает архив `/root/four-migration-release.tgz` и закрытые файлы `/root/four-migration-admin.env`, `/root/four-migration-mail.env`. Перед изменениями сохраняет конфигурацию в `/srv/four-game-backups`.

### Почасовые бэкапы базы на Яндекс Диск

Установка на сервере: `sudo sh /srv/four-game/scripts/install-yandex-backup.sh`. Подключение: `sudo python3 /usr/local/lib/four-game/setup-yandex-backup.py`; вводятся логин Яндекса и отдельный пароль приложения **«Файлы WebDAV»**. Пароль вводится скрыто, не передаётся в аргументах команд и не хранится в репозитории. Конфигурация находится в `/etc/four-game/yandex-rclone.conf` с правами `root:root 0600`, служба получает её через systemd `LoadCredential`.

После первой успешной загрузки включается `four-game-backup.timer`: запуск каждый час, в начале часа по времени сервера. `Persistent=true` запускает пропущенную проверку после перезагрузки. В папке **`4inrow-backups/database`** на Диске хранятся последние **24** архива; в первые сутки копии постепенно накапливаются. При недоступности Диска предыдущие облачные копии сохраняются, а ошибка записывается в журнал; следующая попытка выполняется в следующий час. Пропущенные снимки задним числом не создаются.

Архив содержит `accounts.json`, согласованный снимок `statistics.sqlite` и `manifest.json` с SHA-256. Копирование SQLite выполняется через online backup API с учётом WAL без остановки игры, целостность снимка и архива проверяется до загрузки. Если аккаунты изменились за время копирования, снимок повторяется. Загруженный архив считывается с Диска и сравнивается по SHA-256; только затем удаляются старые собственные архивы по точному шаблону имени. Сторонние файлы в папке не удаляются. На сервере дополнительно сохраняются последние 24 локальных архива в `/var/lib/four-game-backup/archives`, права каталога `0700`.

Проверка: `systemctl list-timers four-game-backup.timer`, `journalctl -u four-game-backup.service -n 30 --no-pager`, `sudo cat /var/lib/four-game-backup/status.json`. Ручной запуск: `sudo systemctl start four-game-backup.service`. Проверка локального снимка без Диска: `sudo -u fourgame python3 /usr/local/lib/four-game/backup-database.py --snapshot-only`. Тесты: `python3 -m unittest discover -s scripts -p test_backup_database.py -v`.

Для восстановления скачайте нужный архив, проверьте SHA-256 файлов по `manifest.json` и `PRAGMA integrity_check` у SQLite. Остановите `four-game`, сохраните текущую папку данных отдельно, замените **оба** файла в `/srv/four-game-data`, удалите старые `statistics.sqlite-wal` и `statistics.sqlite-shm`, установите владельца `fourgame:fourgame` и права `0600`, затем запустите службу и проверьте `/health`. Исходники, SMTP и административные настройки в эти архивы не входят.

## Уровни

Отдельный одиночный режим **«Уровни»** содержит 40 подготовленных позиций в пяти группах. Все уровни доступны сразу. Вы играете первыми из уже заполненной позиции; задача — победить бота. Можно повторить уровень или после победы перейти к следующему.

Под каждым уровнем сохраняется лучший результат — число **ваших** ходов до победы. Стартовые фишки и ответы бота не учитываются. Поражения и ничьи рекорд не меняют; отмена хода в этом режиме отключена. Для авторизованных игроков пройденные уровни и рекорды хранятся в серверной SQLite (`level_progress`), доступны на других устройствах и сохраняются при переименовании аккаунта. При удалении аккаунта его прогресс удаляется. Гостевые результаты остаются на устройстве. Старый локальный прогресс автоматически переносится в первый аккаунт, в который пользователь войдёт после обновления, один раз. При объединении устройств сохраняется минимальное число ходов. Офлайн-результаты аккаунта кешируются отдельно по пользователям в localStorage (`four-cubed-levels-v1`) и отправляются при восстановлении связи, возвращении в окно, открытии уровней или повторной попытке каждые 30 секунд. Текущая попытка сохраняется на устройстве и продолжается из главного меню. `GET /auth/levels` читает прогресс, `POST /auth/levels` объединяет результаты только для владельца текущей сессии. Рекорды личные и не влияют на публичный Elo; сервер проверяет допустимые номера и число ходов, но не перепроигрывает офлайн-партию.

Бот в уровнях отвечает детерминированно: одинаковая позиция даёт одинаковый ответ, без случайности и зависимости от скорости устройства. Используется средняя стратегия с фиксированным бюджетом 6000 узлов поиска. Обычный режим против AI сохраняет вариативность. После подготовки офлайна уровни доступны без интернета, включая повторный запуск закрытого сайта.

## Задача дня

В главном меню доступна **«Задача дня»**: одна стартовая позиция и одинаковый бот для всех. Новая задача появляется автоматически в **00:00 по Москве**. Сервер заранее готовит сегодня и завтра, сохраняет позиции в SQLite и продолжает расписание после перезапуска.

Генератор создаёт легальные позиции с 24–42 фишками, минимум тремя занятыми слоями и минимум тремя фишками на третьем слое. Он проверяет проходимость против настоящего бота, исключает все победы человека за один или два хода и требует, чтобы найденная победная линия затрагивала третий или более высокий слой. Решения и сведения генератора остаются на сервере. Если все процедурные кандидаты не проходят проверку, используется отдельно проверенная сложная позиция. Месячный тест подтверждает уникальность и качество 31 последовательной задачи.

Счётчик учитывает только ваши ходы после стартовой позиции. Бот — средний с фиксированным бюджетом 6000 узлов и без случайности; отмена ходов отключена. Незавершённая попытка восстанавливается с исходной позицией и той же политикой бота. После смены дня старую попытку можно доиграть, но результат уже не попадёт в таблицу.

Играть можно гостем; для таблицы нужен аккаунт. **«Результаты»** показывает топ 100 за текущий день. Выше игрок с меньшим числом ходов, при равенстве — раньше достигший этого результата, затем по имени. Повторные попытки улучшают личный рекорд, одинаковый или худший результат его не меняет. Elo и обычная статистика партий не изменяются.

`GET /daily` возвращает публичную позицию, таблицу и собственный рекорд. `POST /daily/results` принимает ожидаемого владельца аккаунта, идентификатор задачи и только последовательность столбцов человека. Сервер восстанавливает позицию из своей БД, самостоятельно вычисляет каждый ответ бота и принимает лишь настоящую завершённую победу. Он не доверяет присланному счётчику, доске, фишкам бота или заявленному победителю. Пересчёт выполняется в отдельном ограниченном worker, чтобы не задерживать онлайн-партии; действуют ограничения частоты запросов, размера и очереди. Неотправленные результаты переживают закрытие браузера и повторяются под своим аккаунтом до окончания дня.

Для production нужны оба файла `dist-server/index.js` и `dist-server/daily.worker.js` из `npm run build`. Данные хранятся в существующей SQLite в таблицах `daily_challenges` и `daily_results`; учёт переименования и удаления аккаунтов сохранён. Проверки: `npm test` и `npx playwright test e2e/daily.spec.ts`.

## Офлайн

При первом открытии production-версии игра автоматически сохраняет ресурсы для офлайна в фоне, без дополнительных надписей в главном меню. После завершения загрузки ресурсов сайт можно закрыть и открыть без сети: работают все сложности AI, игра вдвоём на одном устройстве, 40 уровней, настройки и шесть видеопримеров. Установка на домашний экран не обязательна. Для первой загрузки нужен интернет; service worker работает по HTTPS или на localhost. В dev-сборке офлайн-кеширование отключено.

Сборка автоматически формирует полный список статических ресурсов с SHA-256 (`scripts/build-offline.mjs`). Worker `/match-notifications.js` обслуживает офлайн и существующие уведомления. Новая версия принимается только после загрузки и проверки всех файлов; неудачная загрузка оставляет предыдущую версию рабочей. Готовое обновление применяется автоматически после закрытия всех вкладок игры и используется при следующем открытии. Открытая партия не перезагружается автоматически. Запросы аккаунтов, админ-панели, статистики, рейтинга, телеметрии и онлайн-соединения не кешируются. Браузер может удалить данные сайта при очистке или нехватке места; тогда потребуется подготовить офлайн заново.

Незавершённая одиночная или локальная партия сохраняется на устройстве, в том числе попытка уровня. После повторного открытия или перезагрузки игры во время партии появляется баннер **«Продолжить партию?»** с кнопками **«Продолжить»** и **«Не продолжать»**. Внутри текущего запуска баннер повторно не показывается. Подтверждённый выход из партии в меню удаляет её сохранение; закрытие браузера в меню не предлагает вернуть завершённую таким образом попытку. Продолжение восстанавливает поле, режим, сложность, время и выбранный вид; прерванный ход AI рассчитывается заново. Отказ или закрытие баннера удаляет это сохранение, и предложение не повторяется. Основная кнопка меню остаётся рейтинговой игрой. Сохранение доступно только тому же локальному профилю или гостю. Начало другой локальной партии заменяет сохранение; онлайн-партии этим механизмом не сохраняются.

Для офлайн-прогресса запоминается только никнейм последнего вошедшего игрока, без пароля, почты или токенов. Это локальный профиль, не подтверждение авторизации. При возвращении сети аккаунт проверяется сервером. Рекорды уровней и очередь результатов завершённых партий переживают закрытие браузера и синхронизируются только под своим аккаунтом. Офлайн-партии не изменяют Elo. Проверка реального запуска после полного закрытия браузера: `npm run test:offline`.

Позиции находятся в `src/game/levels/levels.json`. Для каждой есть проверенная выигрышная последовательность в `solutions.json`: тесты проигрывают все 40 решений против настоящей стратегии бота. Это подтверждение проходимости, а не минимально возможного числа ходов. `scripts/generate-levels.ts` воспроизводимо генерирует набор; при изменении позиций или стратегии нужно перепроверить решения и версионировать рекорды, чтобы старые результаты не относились к новым задачам.

## Аккаунты

Кнопка с именем в шапке открывает **Личный кабинет**. В обзоре показаны профиль, дата регистрации, Elo, текущая лига, прогресс до следующей лиги, рейтинговые игры, общая статистика, процент побед и последние партии. Оттуда можно открыть полную историю. Раздел **Безопасность** позволяет сменить пароль после проверки текущего; остальные сеансы завершаются, а текущее устройство остаётся авторизованным. Для регистрации нужны уникальное имя пользователя (3–24 английские буквы, цифры или `_`; регистр букв при проверке уникальности не учитывается), уникальный email и пароль от 8 символов. Новый аккаунт начинает работать после перехода по одноразовой ссылке из письма; ссылка действует 24 часа. Ссылка сброса пароля действует 1 час и завершает старые сессии. Вход сохраняется на 30 дней в HttpOnly cookie. Пароли хранятся на сервере в виде `scrypt`-хешей, токены сессий, подтверждения и сброса — только в виде SHA-256-хешей. Аккаунты, созданные до добавления email, продолжают входить по имени и паролю. Без входа сервер выдаёт имя вида `Гость_123456`; на одном устройстве оно сохраняется между посещениями. Имя текущей партии фиксируется при её начале.

Аккаунты и сессии сохраняются в `data/accounts.json` по умолчанию. Задайте `FOUR_AUTH_FILE` для постоянного расположения за пределами папки релиза, например `/srv/four-game-data/accounts.json`. Для писем нужны `RESEND_API_KEY`, `FOUR_PUBLIC_URL` (например `https://4inrow.ru`) и необязательный `FOUR_MAIL_FROM` (по умолчанию `FOUR³ <no-reply@4inrow.ru>`). Статистика хранится в SQLite: `FOUR_STATS_FILE`, по умолчанию `statistics.sqlite` рядом с файлом аккаунтов. На сервере это `/srv/four-game-data/statistics.sqlite`. Для резервной копии остановите службу и скопируйте всю папку данных вместе с файлами SQLite WAL/SHM, если они есть; затем снова запустите службу. Данные не входят в архив исходников. Для публичного доступа к регистрации и входу обязателен HTTPS.

## Онлайн-лобби

**Рейтинговая игра** в главном меню сразу ставит игрока в очередь. Когда находится пара, оба получают предложение матча и должны принять его за 15 секунд. Партия начинается только после согласия обоих. При отказе или потере связи соперник возвращается в очередь; при истечении времени игрок, который уже подтвердил матч, продолжает поиск, а не ответивший выходит из очереди. Поиск можно отменить. После начала игры действуют обычные онлайн-правила, включая восстановление партии и реванш.

При найденном сопернике звучит короткий сигнал, меняется заголовок вкладки и появляется системное уведомление, если браузер разрешил уведомления. Разрешение запрашивается при нажатии «Рейтинговая игра»; если соперник найден раньше ответа на запрос, уведомление дождётся разрешения, пока предложение ещё действует. Отказ не мешает играть. Подсказки о разрешениях и установке на домашний экран в окне поиска не отображаются; запрос разрешения и доставка уведомлений сохранены. На iPhone/iPad откройте игру через «Поделиться → На экран Домой», затем запустите с иконки и разрешите уведомления. Для этого добавлены manifest и PNG-иконки; обычная вкладка iOS системные уведомления не поддерживает. Требуется HTTPS с действительным сертификатом. Громкость и отключение звука учитываются. Уведомление закрывается при принятии, отмене и истечении предложения; нажатие возвращает к вкладке игры, но не принимает матч автоматически. `public/match-notifications.js` объединяет уведомления и версионированное офлайн-кеширование игры. После сворачивания на смартфоне или обрыва сети поиск автоматически восстанавливается при возвращении в игру. Во время восстановления показано «Восстанавливаем поиск…»; ручная отмена отключает восстановление. Короткая перезагрузка страницы тоже сохраняет поиск (до 5 минут). Если оба игрока уже приняли матч и ответ сервера потерялся, восстанавливается созданная партия, без повторного подбора. Отключённый игрок не остаётся соперником в очереди: при возврате поиск продолжается. Это уведомление активной браузерной сессии, а не Push: закрытая или приостановленная ОС вкладка не гарантирует получение сигнала. Ограничения платформы: [MDN Notifications](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerRegistration/showNotification).

### Рейтинг

В главном меню кнопка **Рейтинг игроков** открывает публичный топ‑100: место, никнейм, Elo и число рейтинговых партий. Таблица доступна гостям и обновляется при открытии или по кнопке обновления. Включены активные подтверждённые аккаунты (старые аккаунты без email тоже доступны); новые игроки начинают с 1000 Elo и нуля партий. Заблокированные и удалённые аккаунты не показываются. При равном Elo выше игрок с большим числом рейтинговых партий, затем — по никнейму. Места последовательные, от 1 до 100. Endpoint `GET /auth/leaderboard` возвращает только публичные поля.

Авторизованные игроки ищут соперника среди аккаунтов, гости — среди гостей без рейтинга. Для самого давно ожидающего игрока выбирается ближайший по рейтингу из уже ожидающих подходящих соперников; минимального порога разницы нет, чтобы не блокировать игру при небольшой аудитории. В интерфейсе предложения явно указано, будет ли матч рейтинговым. Первый ход случайный.

- Стартовый рейтинг — **1000**, постоянный коэффициент **K = 32**. Ожидаемый результат `E = 1 / (1 + 10^((рейтинг соперника − ваш рейтинг) / 400))`. Изменение первого игрока: округление `32 × (S − E)` до ближайшего целого, где `S = 1` за победу, `0.5` за ничью, `0` за поражение. Второй получает строго противоположное изменение. При точной половине округление направлено вверх.
- Победа над равным соперником: **+16**, на 200 очков сильнее: **+24**, на 400 сильнее: **+29**. Победа над соперником на 200 слабее: **+8**, на 400 слабее: **+3**. За поражение списывается выигрыш соперника. При ничьей равные не меняют рейтинг; слабейший получает часть очков сильнейшего (при разнице 400 — **13**).
- За решающий результат переносится минимум 1 очко, максимум 32. Рейтинг не опускается ниже 0: перенос ограничен остатком проигравшего (при нулевом остатке переноса нет). Отдельных бонусов за серию, скорость, число ходов и новичков нет, чтобы не создавать способы искусственно увеличивать общую сумму очков.
- Очки начисляются только за первую партию после подтверждённого рейтингового поиска двух разных аккаунтов. Личные лобби, AI, локальные игры и реванши очков не дают. Для одной пары учитываются максимум **3 встречи за скользящие 24 часа**, последующие — без очков. Это ограничение повторных встреч, а не полноценная защита от сговора нескольких аккаунтов.
- На ход **90 секунд**, после разрыва соединения — до **60 секунд** на возврат. Лимит действует и в нерейтинговых реваншах после первой партии; после каждого хода начинается новый отсчёт. Оставшиеся секунды постоянно показаны справа от статуса «Ваш ход» / «Ход соперника»; во время согласованной паузы значение замирает. В личном лобби без ограничения времени на этом месте отображается «— сек». Таймер хода не останавливается при разрыве связи: срабатывает более ранний срок. Проверка тайм-аутов выполняется каждые 5 секунд и перед командами. Сдача/выход после принятия обоими, истечение времени хода или возврата — поражение; рейтинг пересчитывается только за первую рейтинговую партию, но не за реванш. Отказ от предложения до начала не штрафуется. Перезагрузка страницы не сбрасывает срок хода. При техническом перезапуске сервера незавершённые комнаты отменяются без изменения рейтинга.
- Один аккаунт может участвовать только в одном рейтинговом поиске/матче одновременно. Результат, рейтинг и запись истории сохраняются сервером в одной SQLite-транзакции с уникальным ID партии. Повтор запроса, переподключение и скрытие записи из истории не дают повторных очков и не откатывают рейтинг. Старые партии до введения рейтинга не пересчитываются.

Текущие очки, лига и прогресс до следующей лиги видны в личном кабинете; очки также показаны в истории и рейтинговом матче. В конце матча и записи истории отображается изменение Elo.

1. Нажмите **Онлайн** и выберите **Создать лобби**. В лобби будет указано имя аккаунта либо гостевое имя.
2. Передайте другу код — ровно пять английских букв, например `ABCDE`.
3. Друг открывает тот же сайт, выбирает **Онлайн**, вводит код и нажимает **Войти в лобби**. Строчные буквы принимаются.
4. Создатель ходит первым графитом, второй игрок играет светлыми. Сервер проверяет очередь, заполнение столбцов и победу, затем передаёт одинаковое состояние обоим игрокам.

Пока второй игрок не подключился или соединение потеряно, ходы заблокированы. После обновления страницы в той же вкладке место и партия восстанавливаются автоматически: секрет восстановления хранится в `sessionStorage`, отдельно от общедоступного кода лобби. На возвращение после разрыва даётся пять минут. Закрытие вкладки может удалить этот секрет.

После рейтинговой партии отдельный экран анимирует изменение Elo и предлагает реванш с тем же соперником. Реванш начинается только после согласия обоих, сохраняет таймер хода и не влияет на рейтинг. Отмена ходов и односторонний перезапуск в онлайне недоступны. Меню и настройки не приостанавливают партию для соперника. **Покинуть лобби** закрывает его для обоих игроков после подтверждения.

Для общей паузы нажмите **Пауза → Предложить паузу · 2 мин**. Соперник должен принять запрос в течение 30 секунд; до согласия игра и таймер хода продолжаются. После принятия сервер блокирует ходы на 120 секунд, останавливает игровое время и таймер рейтингового хода, затем автоматически возобновляет партию. Кнопка **Готов** позволяет продолжить раньше: когда её нажмут оба игрока, пауза закончится сразу. Одного нажатия недостаточно; готовность сохраняется после обновления страницы, а таймер хода получает только фактически проведённое на паузе время. На двоих доступна одна принятая пауза за партию; взаимный реванш восстанавливает её. Запрос можно отклонить или отменить, это не расходует паузу; повторный запрос доступен через 30 секунд после предыдущего. Обновление страницы сохраняет оставшееся время. Время согласованной паузы также не расходует срок возвращения после обрыва связи.

## Размещение для игры через интернет

Текущий сервер: **https://4inrow.ru/**, приложение `/srv/four-game`, служба `four-game`. HTTPS и автоматическое продление сертификата описаны в разделе «Сервер». Подключение с рабочего компьютера: `ssh four-game-server`, ключ — `%USERPROFILE%/.ssh/four-ai-deploy-139-100-221-126`. Старый ключ `four-ai-deploy` сохранён, старому серверу соответствует алиас `four-game-server-old`. **По прямому указанию владельца SSH-ключи удаляются только по его отдельной просьбе.** Ключи находятся вне проекта и не включаются в архивы исходников.

`localhost` доступен только на текущем устройстве. Для игроков из разных сетей разместите приложение на Node-хостинге с поддержкой WebSocket, с одним экземпляром сервера:

```sh
npm ci
npm run build
npm start
```

В production сервер по умолчанию слушает `127.0.0.1`, в dev — `0.0.0.0`; переменная `HOST` переопределяет адрес, `PORT` задаёт порт (по умолчанию 3001). Он отдаёт сайт, HTTP API `/auth` и WebSocket `/online` с одного адреса; проверка доступности — `GET /health`. Для публичного размещения нужен HTTPS reverse proxy с WebSocket Upgrade; браузер автоматически выберет `wss://`. Для запуска собранного приложения нужны `dist/`, `dist-server/`, `package.json`, `package-lock.json` и production-зависимости (`npm ci --omit=dev`).

Комнаты хранятся в памяти одного процесса: перезапуск сервера закрывает текущие лобби, а несколько несогласованных серверных экземпляров не поддерживаются. Лобби удаляется после пяти минут отсутствия игрока либо двух часов бездействия. Для масштабирования и сохранения после рестарта следующим этапом потребуется внешнее хранилище.

## Правила и управление

Основной интерфейс занимает один экран на компьютере и телефоне: высота ограничена видимой областью браузера, поле получает оставшееся место. В меню доступны рейтинговая игра, AI, игра вдвоём и онлайн-лобби; правила открываются отдельно. На компьютере режимы и данные партии расположены слева от поля, на телефоне меню находится под доской. В горизонтальной ориентации управление расположено сбоку. Повтор партии и реванш доступны на экране результата. Диалоги сохраняют внутреннюю прокрутку при увеличенном тексте или открытой клавиатуре, чтобы элементы оставались доступными.

- 25 столбцов на основании 5×5. В каждом — максимум пять фишек.
- Нажмите на столбец: фишка займёт нижнее свободное место. Игроки ходят по очереди.
- Четыре или пять своих фишек подряд побеждают: по горизонтали, вертикали, диагонали плоскости или пространственной диагонали.
- Перетаскивание вращает поле, колёсико и жест двумя пальцами приближают. Вращение не считается ходом.
- **Рентген** показывает структуру башен. В меню **Вид** можно независимо включать любые слои (например, 2, 4 и 5) и выбирать положение камеры. Новый ход возвращает все слои. Громкость звуков регулируется ползунком в настройках; кнопка в шапке выключает звук.
- **Esc** — пауза, **R** — вернуть камеру, **X** — рентген. Кнопки доступны с клавиатуры.
- **Отменить** возвращает ход; против AI возвращает пару ходов. После завершения доступны реванш и пошаговый повтор.

Первое начало локальной игры открывает короткое обучение; раздел «Как играть» доступен во всех режимах. Настройки, просмотр обучения и последняя сложность AI сохраняются в localStorage. Локальная партия не сохраняется при перезагрузке; онлайн-партия восстанавливается с сервера.

## Модель доски

Доска сделана в Blender: единый скруглённый корпус, 25 плавных посадочных лунок, графитовое основание и сатиновые ободки. Исходник — `assets/board/four-board.blend`, игровая модель — `public/models/four-board.glb`. Геометрия имеет замкнутые поверхности; отчёт проверки — `assets/board/geometry-report.json`.

`scripts/build-board.py` содержит четыре этапа построения для Python-консоли Blender: `stage1()` — корпус, `stage2()` — лунки, `stage3()` — отделка, `stage4()` — студийная сцена, сохранение и экспорт. Скрипт сначала сохраняет резервную копию открытой сцены. Blender нужен только для редактирования модели; для запуска и сборки игры он не требуется.

Сетка сохраняет шаг 1.09 и координаты существующей игры. При ручном экспорте GLB выбирайте только объекты коллекции `BOARD - export`, с преобразованием в Y-up; камеры и студийный пол в игровой файл не входят.

## Архитектура

| Модуль              | Ответственность                                                                                         |
| ------------------- | ------------------------------------------------------------------------------------------------------- |
| `src/game/core`     | Чистый TypeScript: immutable snapshots, гравитация, 13 осей победы, история, undo, replay, сериализация |
| `src/game/ai`       | Три уровня, тактические угрозы, эвристика, negamax/alpha-beta, отменяемый Web Worker                    |
| `src/store`         | Zustand: фазы игры, блокировка ввода, таймер, отмена незавершённого AI, настройки                       |
| `src/scene`         | Three.js / React Three Fiber / Drei: геометрия, материалы, камера, picking и эффекты                    |
| `src/ui`, `src/app` | React, CSS Modules, Motion: меню, HUD, диалоги, обучение и адаптивная компоновка                        |
| `src/audio`         | Синтезированные Web Audio эффекты и необязательный тихий фоновый аккорд                                 |
| `src/network`       | Типизированный протокол, WebSocket-клиент, восстановление соединения и секрет места в лобби             |
| `server`            | Авторитетное состояние партий, коды лобби, проверка команд, реванш, heartbeat и очистка комнат          |
| `e2e`               | Playwright: настоящие клики по canvas и касания, полная партия, мобильные размеры                       |

Логические координаты: `x/y` — основание, `z` — высота. Индекс ячейки: `x + y*5 + z*25`. Three.js преобразует высоту в мировую ось Y только при отрисовке.

Движок принимает только столбец и самостоятельно проверяет/вычисляет высоту. Сериализованный формат версионирован; загрузка заново проигрывает и проверяет все ходы. В сцене нет вычисления победителя.

Все уровни AI забирают немедленную победу и обычно закрывают обязательную угрозу, избегая ходов, открывающих сопернику победную клетку этажом выше. Лёгкий выбирает из четырёх лучших безопасных вариантов. Средний и сложный используют поиск ответов с итеративным углублением, отсечением ветвей и кешем повторяющихся позиций: до 4 и 8 полуходов, с бюджетами около 180 и 650 мс соответственно. Вынужденные защиты продолжаются ещё до 6 полуходов за границей обычного поиска; учитываются двойные угрозы и доступность клеток по высоте. Фактически достигнутая глубина зависит от позиции и скорости устройства. Это ограниченный эвристический поиск, а не решённая стратегия. Расчёт выполняется в Worker, который прекращается при паузе, перезапуске и выходе; устаревшие ответы отбрасываются.

В обычном режиме против среднего AI после первых **10 ходов партии суммарно обоих игроков** бот с вероятностью **7%** пропускает блокировку единственной доступной победной клетки соперника. В остальные 93% таких ситуаций он блокирует как раньше. Проверка делается отдельно на каждом подходящем ходу бота, а не один раз на партию. При ошибке выбирается другой допустимый ход с хорошей позиционной оценкой. Первые десять ходов, собственная немедленная победа бота, позиции с несколькими победными клетками соперника, лёгкий и сложный AI и детерминированный режим «Уровни» этим правилом не меняются.

Онлайн-клиент отправляет `{type:'move', x, y, revision, round}`. Игрок определяется серверной сессией; клиент не назначает себе цвет, высоту или победу. `revision` и `round` отклоняют повторные и устаревшие ходы. При переподключении клиент запрашивает актуальное состояние, а не повторяет отправку хода. Сервер валидирует JSON, ограничивает размер и частоту сообщений и количество комнат/соединений.

В спокойной позиции средний AI с вероятностью 35%, а сложный с вероятностью 25% выбирает другой близкий по оценке ход, если такой найден. Альтернативы берутся из одной полностью завершённой глубины поиска (не менее двух полуходов), с узким допустимым отставанием от лучшей оценки. Эта вариативность близких по оценке ходов не затрагивает немедленную победу, обязательную защиту и найденные форсированные исходы; непроверенные оценки из прерванного поиска не используются.

## История партий

- **История партий** открывается из личного кабинета кнопкой «Вся история». Для авторизованных пользователей сервер хранит число партий, побед, поражений и ничьих, а также последние 50 завершённых матчей для просмотра. После входа в тот же аккаунт история доступна с другого устройства. Названия можно менять; удаление скрывает партию из истории, но не уменьшает общие счётчики.
- Онлайн-результаты сохраняет сам сервер для каждого авторизованного участника, в том числе в рейтинговой игре. Одна партия учитывается один раз. В режимах вдвоём и против AI результат относится к аккаунту первого игрока, который был авторизован при старте и завершении партии. Сервер проверяет завершение и легальность последовательности ходов; такие результаты не предназначены для защищённого соревновательного рейтинга, поскольку ходы поступают из браузера.
- Гости не сохраняют статистику. Старая история из localStorage автоматически не переносится: в ней нельзя достоверно определить владельца. При ошибке отправки локальной партии откройте историю и нажмите «Повторить» до закрытия страницы; неподтверждённый результат временно остаётся в памяти вкладки.
- В одном онлайн-лобби первый ход чередуется: в первой партии начинает создатель, во второй — присоединившийся игрок, в третьей — снова создатель. Цвета и места игроков сохраняются, повторы учитывают того, кто начал партию.

## Админ-панель

Панель доступна по адресу `/admin` и не отображается в публичном меню игры. Она показывает зарегистрированных игроков, дату регистрации, имена, email, статус подтверждения, Elo, число рейтинговых игр и общую статистику побед, поражений и ничьих. Дата точно сохраняется для аккаунтов, созданных после появления этого поля; у более старых отображается «До обновления», поскольку раньше дата не записывалась. Есть поиск и постраничный список. В карточке игрока можно изменить имя, email, подтверждение почты и Elo, заблокировать аккаунт, создать временный пароль или безвозвратно удалить аккаунт после ввода его точного имени. Удаление очищает сессии, токены, Elo, рейтинговые записи и всю связанную историю матчей; активная партия отменяется для обоих игроков. Новый временный пароль показывается только один раз. Изменение имени, email, блокировки или пароля завершает активные сессии игрока; хеши паролей никогда не передаются в браузер.

Админ-панель включается только при наличии `FOUR_ADMIN_PASSWORD_HASH`. Создать случайный пароль и совместимый `scrypt`-хеш:

```sh
npm run admin:credentials
```

Сохраните выведенный хеш в защищённой переменной окружения сервиса, а пароль — в менеджере паролей. Логин по умолчанию — `admin`; его можно заменить через `FOUR_ADMIN_USERNAME`. Админ-сессия хранится в отдельной `HttpOnly`, `SameSite=Strict` cookie, живёт 12 часов и сбрасывается при перезапуске сервера. Вход ограничен десятью попытками с одного IP в минуту. Страница помечена `noindex,nofollow`.

## Проверки

В админ-панели `/admin` вкладка **Статистика** содержит обзор посещений, график по дням (МСК), популярность пяти режимов, устройства, браузеры и домены источников переходов. Раздел **Боты** сравнивает результаты человека против лёгкого, среднего и сложного AI; раздел **Игроки** показывает до 200 активных аккаунтов с разбивкой по режимам и результатами против каждой сложности; **Уровни** — попытки, победы, поражения и рекорд ходов для всех 40 уровней. Есть периоды 7/30/90 дней, произвольный диапазон до 366 дней, фильтры режима и устройства, обновление раз в минуту и CSV текущего раздела.

Аналитика хранится в той же SQLite-базе `FOUR_STATS_FILE`, в таблицах `analytics_sessions`, `analytics_games`, `analytics_meta`; сторонний сервис аналитики не требуется. Посетитель — случайный идентификатор браузера в localStorage, сеанс — идентификатор вкладки в sessionStorage с обновлением после 30 минут отсутствия. Активное время считает только видимую вкладку. Полные URL источников, IP, email и сырые User-Agent в аналитическую базу не записываются. Клиент отправляет `/telemetry` с ограниченным набором событий, сохраняет очередь при потере сети и не отменяет партию при сворачивании браузера. Сервер проверяет события, законченные позиции и пресеты уровней, ограничивает частоту запросов и исключает повторы. Отчёт `/admin-api/analytics` доступен только с админ-сессией.

Онлайн фиксируется сервером: одна партия на два участника, включая реванши из рейтингового поиска; у каждого аккаунта свой результат. Устройство онлайн-партии определяется по последнему известному визиту первого участника. Неизвестные устройства исключаются при фильтрации по конкретному устройству. Незавершённые/текущие партии показаны отдельно от явно прерванных. В режиме «Вдвоём» результаты не входят в персональный процент побед. При первом запуске старые завершённые партии аккаунтов импортируются один раз; неизвестная сложность бота не подставляется задним числом. Посещения, гостевые партии, попытки уровней и сложности AI собираются с момента включения аналитики. При переименовании аккаунта аналитика обновляется, при удалении связи с аккаунтом обезличиваются, агрегаты сохраняются.

Для отдельной проверки админ-дашборда и сбора событий в настоящем браузере после сборки: `node --import tsx scripts/verify-analytics.mjs`. Проверка использует временную базу, временный сервер, тестовые аккаунты и сохраняет скриншоты в `artifacts/analytics-*.png`; production-данные не меняются.

Раздел **Как играть** содержит шесть коротких MP4-роликов, отрендеренных на настоящей модели поля: постановка фишек, горизонталь, вертикаль, диагональ первого слоя, диагональ третьего слоя и объёмная диагональ. Все последовательности проходят через игровые правила с чередованием игроков и опорой под каждой фишкой. Можно остановить, плавно перемотать и повторить пример; полоса воспроизведения обновляется каждый кадр и на компьютерах, и на телефонах. Все шесть видео заранее скачиваются во время начального загрузочного экрана (по два одновременно, с прогрессом), сохраняются в Cache Storage и воспроизводятся из памяти без повторной загрузки. При недоступном хранилище остаётся кэш текущей вкладки. На медленном соединении через 8 секунд можно продолжить игру с фоновой загрузкой; ошибка или тайм-аут видео не блокирует игру. При отключённых анимациях или системном уменьшении движения показывается итоговый кадр до ручного запуска. При ошибке видео остаются изображение и объяснение. При замене роликов необходимо обновить версию кэша в `src/network/tutorialMedia.ts`.

Исходные ходы и тексты: `src/ui/tutorialExamples.ts`. Для повторного рендера запустите `npm run dev`, затем в другом терминале `node scripts/render-tutorial.mjs`. Нужен Chromium/Edge с записью H.264; готовые ролики и постеры сохраняются в `public/tutorial`. Сервер отдаёт MP4 с `video/mp4` и поддержкой HTTP byte ranges для перемотки и мобильных браузеров.

```sh
npm run typecheck
npm run lint
npm run test
npm run build
npm run test:e2e

```

Vitest проверяет все 13 осей, разрывы линий, несколько побед одновременно, полную легальную ничью на 125 ходов, сериализацию, AI и переходы фаз. React Testing Library проверяет клавиатурный фокус диалогов.

`test:production` запускается после `build`: открывает собранную игру через временный Node-сервер, проходит обучение, делает локальный ход, создаёт онлайн-лобби в двух независимых браузерных сессиях и проверяет синхронизацию клика и мобильного касания. Проверяет отсутствие dev API и ошибок консоли. Серверные тесты используют настоящие WebSocket-соединения; браузерные онлайн-тесты покрывают общую победу, взаимный реванш, восстановление вкладки, полный/несуществующий код и выход.

Для проверки уже размещённого сайта задайте `PRODUCTION_URL`: тест использует указанный адрес и не запускает локальный сервер. Пример для PowerShell:

```powershell
$env:PRODUCTION_URL = 'http://SERVER_IP'
npm run test:production
Remove-Item Env:PRODUCTION_URL
```

Проверка создаёт временное лобби и выполняет ходы в двух браузерных сессиях.

Первичная установка браузеров:

```sh
npx playwright install chromium firefox webkit
```

Playwright запускает доступный Chromium или установленный Edge; Firefox и WebKit добавляются при наличии установленных бинарников. Полная принудительная матрица и подробности — в [e2e/README.md](e2e/README.md). Эмуляция телефона проверяет viewport и touch-события, но не заменяет проверку на реальных устройствах.

Отчёт: `playwright-report/index.html`; скриншоты и traces: `test-results/`. Проекции столбцов для реальных pixel-click проверок доступны через `window.__fourScene` **только в dev-сборке**. Тесты не подменяют игровые ходы вызовами store.

## Границы первого MVP

Нет зрителей и серверного Web Push. Есть офлайн-PWA и уведомления из открытой страницы. Аккаунты хранятся в файле, статистика и рейтинг — в SQLite; приложение рассчитано на один экземпляр сервера. Незавершённые онлайн-комнаты остаются в памяти процесса. Для 3D требуется WebGL; при недоступности показывается сообщение о восстановлении. Управление слепым пользователем через отдельную текстовую доску пока не реализовано.

Производительность и аппаратное ускорение зависят от устройства. Разрешение 3D-сцены учитывает плотность экрана до DPR 3 и бюджет в 3 млн пикселей (минимум DPR 1). Выбранное разрешение сохраняется при обновлении таймера и ходах, поэтому плотные экраны телефонов не переключаются на пиксельное изображение. HDRI и тяжёлого постпроцессинга нет. Мобильные браузеры, Safari и Firefox требуют отдельной проверки; успешные прогоны Edge не считаются их сертификацией.
